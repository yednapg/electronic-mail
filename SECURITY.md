# Security policy

## Supported release

Security fixes are provided for the most recent publicly distributed Electronic Mail build. The publisher may pause downloads while a serious issue is investigated. Users should install the latest signed and notarized build linked from the official download page.

## Report a vulnerability privately

Use the monitored address on the official Electronic Mail support page and put `Security report` in the subject. Do not file a public issue for a suspected vulnerability.

Include the app version/build, macOS version, the affected feature, reproducible steps, impact, and a safe proof of concept. A correlation ID and approximate time are useful. Do **not** send Google passwords, OAuth codes or tokens, session cookies, private keys, raw email bodies, attachments, production database exports, or screenshots containing private mail.

The support/on-call owner must acknowledge, triage, and coordinate disclosure using the severity targets approved for the production launch. Repository automation cannot promise response times until that accountable roster and policy are published.

## Safe handling

Test only accounts and data you own or are explicitly authorized to use. Do not disrupt other users, send spam, exfiltrate data, or access production infrastructure. If you encounter user data unexpectedly, stop testing, preserve minimal metadata needed to report the issue, and delete local copies after the publisher confirms receipt.
